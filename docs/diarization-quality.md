# Контроль качества диаризации

## Реализованный конвейер

PyAnnote обрабатывается через обычную `speaker_diarization`, поэтому одновременная речь не заменяется эксклюзивной разметкой. Монофонический overlap распознаётся GigaAM один раз, сохраняется с `speaker_id=UNKNOWN` и содержит кандидатов в `overlap_speaker_ids`. Текст не копируется каждому кандидату.

Длинная реплика ограничивается `ASR_MAX_SEGMENT_SECONDS`, но перед жёсткой границей система ищет тихую паузу. Параметры:

```dotenv
ASR_SPLIT_ON_SILENCE=true
ASR_SILENCE_THRESHOLD_DB=-38
ASR_MIN_SILENCE_SECONDS=0.18
ASR_PAUSE_SEARCH_SECONDS=2.0
```

Сегменты не объединяются через смену говорящего или границу overlap.

## Оценка по эталону

Эталон хранится в RTTM. Запуск внутри worker:

```bash
python /app/scripts/evaluate-diarization.py \
  /data/evaluation/meeting-01.rttm \
  /data/jobs/JOB_ID/diarization.json
```

Команда выводит DER, JER и составляющие ошибки. По умолчанию overlap учитывается. `--skip-overlap` нужен только для отдельного диагностического сравнения, а `--collar 0.25` добавляет допуск 250 мс около эталонных границ.

## Speech separation

Separation следует запускать только для интервалов `overlap=true`, не для всей записи. Такие интервалы режутся максимум по `OVERLAP_SEPARATION_MAX_SECONDS=8` и получают `separation_eligible=true`. Это готовая отдельная очередь кандидатов для будущей последовательной обработки.

Этап намеренно не активируется без отдельной локальной модели separation: текущий `speaker-diarization-community-1` возвращает разметку говорящих, но не разделённые аудиоканалы. Перед включением нужно проверить соответствие каналов говорящим и пиковую VRAM; на GTX 1630 4 ГБ separation должен выполняться по одному короткому фрагменту после освобождения основной модели.
